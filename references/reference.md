0.19 (`~/.hermes/hermes-agent/cron/jobs.py`, `cron/scheduler.py`,
`tools/cronjob_tools.py`). Читай раздел, который нужен, — файл не рассчитан на чтение

## Инструмент `cronjob`

Единый инструмент с действиями: `create`, `list`, `update`, `pause`, `resume`,
`remove`, `run`.

- `job_id` обязателен для всех действий кроме `create`/`list`. Принимается id **или**
  имя (регистронезависимо); неоднозначное имя даёт ошибку, а не случайный выбор.
- **Никогда не угадывай id** — сначала `list`, потом действие.
- `list` по умолчанию показывает **только включённые** задачи. Отсутствие задачи в
  списке не означает, что её нет: она может быть выключена или на паузе.
- `run` не запускает задачу немедленно — ставит её в очередь на ближайший тик.
- `update` со сменой `schedule` у **не приостановленной** задачи попутно ставит
  `enabled=true` и `state=scheduled`. У приостановленной — не трогает состояние.

## Поля задачи

| Поле | Смысл | Замечания |
|------|-------|-----------|
| `id` | 12-символьный идентификатор | неизменяем; используется как имя каталога вывода |
| `name` | человекочитаемое имя | по нему тоже можно адресовать задачу |
| `prompt` | задание для агента | должен быть самодостаточным (свежая сессия) |
| `schedule` | объект: `kind` + `expr`/`minutes`/`run_at` | источник правды по каденции |
| `schedule_display` | строка для показа | производное, не редактировать вручную |
| `enabled` | участвует ли задача в скане | **структурное** поле, едет в git; у одноразовой после срабатывания планировщик сам ставит `false` — автосинк объясняет это в `HANDOFF.md` §8 |
| `state` | `scheduled` / `paused` / `error` / `completed` | **волатильное**, в git не едет |
| `fire_claim`, `run_claim` | лизы планировщика: кто и когда взял срабатывание / запуск (защита от дубля) | волатильные; ядро само ставит и обнуляет, снимок вырезает |
| `paused_at`, `paused_reason` | когда и почему поставлена пауза | волатильные |
| `next_run_at` | момент следующего запуска | волатильное; пересчитывается |
| `last_run_at`, `last_status`, `last_error` | итог последнего запуска | волатильные |
| `repeat.times` / `repeat.completed` | лимит и счётчик запусков | `times: null` = бесконечно |
| `deliver` | цель доставки | см. ниже |
| `origin` | откуда задача создана | используется при `deliver: origin` |
| `skills` / `skill` | скиллы, загружаемые перед промптом | порядок значим |
| `enabled_toolsets` | ограничение тулсетов | сильно режет входные токены |
| `script` | путь к скрипту | относительный резолвится от `~/.hermes/scripts/` |
| `no_agent` | скрипт вместо LLM | требует `script`; `prompt`/`skills` игнорируются |
| `context_from` | id задач, чей вывод подмешать | список или одна строка |
| `model` / `provider` | пин модели | снимок делается при создании |
| `workdir` | рабочий каталог задачи | подмешивает `AGENTS.md`/`CLAUDE.md`; такие задачи идут последовательно |
| `attach_to_session` | делает доставку продолжаемой | на платформах с ветками откроет свою ветку |

## Формы расписания

| Форма | Пример | Вид |
|-------|--------|-----|
| относительная задержка | `30m`, `2h`, `1d` | одноразовая |
| интервал | `every 30m`, `every 2h`, `every 1d` | повторяющаяся |
| cron-выражение (5 полей) | `0 9 * * *`, `0 20 * * 0-4`, `0 */6 * * *` | повторяющаяся |
| ISO-таймстемп | `2026-08-03T00:01:00` | одноразовая |

Время считается в `timezone` из `config.yaml` (у Мии `Asia/Bangkok`). День недели в
cron: `0` = воскресенье; `1-5` — будни; `0-4` — вс–чт (то есть «вечер перед учебным днём»).

**Окно опоздания (grace).** Половина периода расписания, но не меньше 120 с и не
больше 2 часов. Опоздание внутри окна — обычный догон. Опоздание больше окна:
накопленные пропуски **схлопываются** (пачка не выстреливает залпом), но задача
**один раз срабатывает сразу**. Одноразовая задача на момент, ушедший в прошлое
дальше 120 с (`ONESHOT_GRACE_SECONDS`), при создании и правке **отклоняется**.

**Смена часового пояса** после сохранения задачи чинится автоматически: если
сохранённое настенное время ещё в будущем, `next_run_at` пересчитывается из
выражения, чтобы задача не сработала на несколько часов раньше и потом ещё раз.

## Доставка

| Значение `deliver` | Куда |
|--------------------|------|
| опущено / `origin` | обратно в чат и **ветку**, где задача создана (рекомендуется) |
| `local` | только файл в `cron/output/`, сообщения нет |
| `platform:chat_id:thread_id` | конкретный адрес, напр. `telegram:-1003727229450:421` |
| `platform:chat_id` | тот же чат, но **ветка теряется** |
| `all` | во все подключённые домашние каналы; резолвится в момент запуска |
| комбинация | `origin,all` |

Финальный ответ агента доставляется автоматически — **не вызывай `send_message` из
промпта крона**, иначе человек получит сообщение дважды. Дубль обычно заводят не прямым
вызовом, а формулировкой: промпт «Отправь в Telegram…» плюс `enabled_toolsets:
["telegram"]` — модель послушно шлёт сама, а крон следом доставляет её ответ. Проси
**сформулировать**, а не отправить, и не выдавай такой задаче тулсет `telegram`.

⚠️ **`origin` — это чат создания, а не адресат.** Значение резолвится через поле
`origin.chat_id`. Задача, заведённая в детском чате, но написанная для родителей, при
`deliver: origin` уедет ребёнку. Прежде чем сохранить — раскрой `origin` в конкретные
chat_id/thread_id и сверь с тем, кому обращён текст.

Подавление доставки: `[SILENT]` в ответе агента — вывод сохранится в файл, сообщение
не уйдёт. Ошибочные запуски доставляются всегда, вне зависимости от `[SILENT]`.

`wrap_response: false` в `config.yaml` (так у Мии) — сообщение уходит без служебной
шапки «Cronjob Response».

## Скриптовые режимы

**`no_agent: true`** — скрипт и есть задача, stdout уходит дословно:
- непустой stdout → сообщение;
- пустой stdout → **тишина** (ничего не отправляется);
- ненулевой код возврата или таймаут → алерт об ошибке.

Таймаут скрипта — `cron.script_timeout_seconds` (по умолчанию 3600 с).
`.sh`/`.bash` исполняются через bash, остальные расширения — через Python.

**`script` без `no_agent`** — прекчек: stdout подмешивается в промпт как контекст.
Последняя непустая строка stdout читается как гейт:

```json
{"wakeAgent": false}
```

→ агент не будится (ноль токенов). Любой другой вывод — обычное пробуждение.
Гейт работает в обоих режимах.

**Локальный патч Мии** расширяет гейт до маршрутизации:

```json
{"wakeAgent": true, "deliver": "telegram:-1003804792291:2542"}
```

перенаправляет доставку **этого запуска**. Принимаются только `origin`, `local` и
числовой `platform:chat_id[:thread_id]`; в `jobs.json` override не записывается.

## Цепочки задач (`context_from`)

Задача B получает в контекст **последний завершённый** вывод задачи A:

```
A: 07:00 — собрать сырьё
B: 07:30 — context_from=[A.id] — отранжировать и написать сводку
```

`context_from` не ждёт задачу, которая выполняется в том же тике, — берётся последний
готовый вывод. Разноси такие пары по времени с запасом.

## Жизненный цикл и состояния

- `scheduled` — ждёт своего времени.
- `paused` — приостановлена (вместе с `enabled=false`).
- `error` — повторяющаяся задача не смогла вычислить следующий запуск (например,
  в окружении gateway пропал `croniter`). Такая задача намеренно **не выключается
  молча** — иначе пропавшая зависимость выглядела бы как «задача завершилась».
- `completed` — одноразовая отработала (`enabled` становится `false`).

Задача с лимитом `repeat.times` при достижении лимита **удаляется**. Догоняющий
запуск тоже тратит одно срабатывание из лимита.

## Что где лежит на диске

| Путь | Что |
|------|-----|
| `~/.hermes/cron/jobs.json` | живое состояние задач (рантайм, не в git) |
| `~/.hermes/cron/jobs.tracked.json` | одобренная структура (в git, `main`) |
| `~/.hermes/cron/jobs.baseline.json` | снимок на конец прошлого синка — база 3-way (рантайм) |
| `~/.hermes/cron/executions.db` | durable-история попыток запуска (sqlite) |
| `~/.hermes/cron/output/<job_id>/` | вывод каждого запуска, markdown |
| `~/.hermes/cron/ticker_heartbeat` | отметка последнего тика планировщика |
| `~/.hermes/cron/ticker_last_success` | отметка последнего успешного тика |
| `~/.hermes/logs/agent.log` | строки `cron.scheduler: Job '<id>': …` |
| `~/.hermes/scripts/` | скрипты для `script`-задач |

Статусы в `executions.db`: `claimed`, `running`, `completed`, `failed`, `unknown`.

## CLI `hermes cron`

```
hermes cron list
hermes cron create "0 9 * * 1-5" "..."   (alias: add)
hermes cron edit <id> --schedule "every 4h"
hermes cron edit <id> --script reminder-x.py --no-agent   (перевод в script-only)
hermes cron edit <id> --deliver telegram:-1003727229450:95
hermes cron pause <id> | resume <id> | run <id> | remove <id>
hermes cron status
hermes cron runs <id> --limit 20          (alias: history)
hermes cron tick
```

⚠️ На сервере Мии `hermes` **не лежит в PATH неинтерактивного ssh**. Вызывай полным
путём: `~/.hermes/hermes-agent/venv/bin/hermes cron list`.

⚠️ `hermes cron tick` прогоняет due-задачи **по-настоящему** — это не «показать, что
запустилось бы». Для проверки используй `cron-doctor.py`.

⚠️ У `cron edit` **нет флага для `enabled_toolsets`** — при переводе задачи в script-only
тулсеты останутся от прежней LLM-версии. Добивать пустым списком отдельно:
`jobs.update_job("<id>", {"enabled_toolsets": []})` из `cron/jobs.py`. Переключение
`--no-agent` при этом само обнуляет `model_snapshot`/`provider_snapshot`.

## Настройки в config.yaml

```yaml
timezone: Asia/Bangkok
cron:
  wrap_response: false          # без служебной шапки в сообщении
  # mirror_delivery: true       # продолжаемые доставки (глобально)
  # script_timeout_seconds: 1800
approvals:
  cron_mode: deny               # опасная команда в кроне отклоняется, а не ждёт
```

Модель: пин задачи → `cron.model` → глобальный дефолт. Провайдер и модель
фиксируются снимком при создании, чтобы смена глобального дефолта не увела задачу
незаметно.
